# Isolated MV3 file URL probe

This directory is a **separate experimental extension**. It never changes Clockoli's production manifest, logic, database, or agent logs. The only browser permissions are `alarms` and `host_permissions: ["file:///*"]`; there is no remote host permission, upload call, content script, or daemon. It reads a bounded 4 KiB sample of one existing JSONL per provider without printing or persisting that text, and fetches directory index HTML to count `.jsonl` paths. The Node runner uses read-only directory metadata to choose an existing sample path; it does not read source file contents itself.

## Reproduce

1. From the repository root, run `node experiments/local-agent-file-url/live-check.mjs` for an **isolated Google Chrome profile**. Chrome 158 on this machine needs the native **Load unpacked** picker: select the absolute `experiments/local-agent-file-url/` directory. In this experimental extension's `chrome://extensions` details, enable **Allow access to file URLs** if it is off. `chrome.extension.isAllowedFileSchemeAccess()` records its actual setting. Nothing is enabled on the installed Clockoli.
2. The runner uses this extension's own page to save only the two root file URLs and one existing nested JSONL file URL per provider. It runs a page-initiated worker scan, closes the extension page, waits for a real `chrome.alarms` scan, fully closes the isolated browser, relaunches its **same temporary profile**, and waits for a startup/alarm scan without any extension page. It prints only browser version, permission switch state, trigger, directory and file counts, bounded sample byte count, safe error codes, and run numbers. The temporary profile is removed when the run ends; your normal browser is never closed.
3. `node experiments/local-agent-file-url/live-check.mjs --chromium` repeats the procedure in Playwright's bundled Chromium. That variant may auto-enable file access for an unpacked extension and is not evidence for branded Google Chrome's initial toggle policy.
4. The synthetic regression `npx playwright test test/file-url-probe.browser.spec.js --workers=1` creates its **own** temporary JSONL fixtures under the Hermes scratch directory, checks nested enumeration and worker file reads before/after closing the page and restarting the browser, then deletes only those temporary fixtures and profile.

## Interpretation and limits

- `file:///*` is an **origin-wide** host permission; its path component cannot restrict access to only `~/.codex/sessions` and `~/.claude/projects`. With file access enabled, a compromised or malicious version of this extension could read other accessible local files. The prototype validates configured URLs against its two expected roots, but those checks are application code, **not** a browser-enforced sandbox. Do not ship this broad permission in Clockoli without an explicit privacy/security decision and a clear user opt-in. Never pass arbitrary file URLs from content scripts or web pages to the worker.
- Directory enumeration is an observed Chromium-generated HTML index (`fetch(file://directory/)` can return **status 0** with an HTML body containing `addRow(...)` entries), not a stable structured directory-list API. The prototype parses only bounded row metadata, never executes the index's scripts, and limits recursion to six levels / 1000 directories / 20000 entries. A changed index format or unavailable directory sets an error rather than proving that no files exist. It fetches only one **known file** per provider to verify read access; it does not parse all discovered logs or produce Clockoli work records.
- An alarm needs Chrome running. A closed browser or sleeping computer cannot continuously execute extension code; a production tracker must retain cursors and catch up on startup, handle log rotation, worker termination, directory-index changes, unavailable files, and data consent. File URL access and File System Access API permissions are distinct mechanisms.

Official references: Chrome extension [permission declarations](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions), [match patterns](https://developer.chrome.com/docs/extensions/develop/concepts/match-patterns), [cross-origin requests](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests), and Chromium's [file access security FAQ](https://chromium.googlesource.com/chromium/src/+/main/extensions/docs/security_faq.md).

## Observed in bundled Chromium 151.0.7922.34

With the isolated extension auto-loaded from the command line, `isAllowedFileSchemeAccess()` returned `true`. Against the **real** Codex and Claude Code trees, a page-initiated worker scan, the next alarm scan with **no extension page**, and an alarm scan **after completely restarting the same isolated browser profile** all succeeded: each run enumerated 501 nested Codex JSONL files in 136 directories and 34 Claude JSONL files in 35 directories, and `fetch(file://...)` returned HTTP 200 and a complete JSONL line within a bounded 4096-byte sample from one known file per provider. No file text was output or persisted. The synthetic browser regression independently passed the same lifecycle and nested enumeration with disposable fixtures. These observations do **not** establish branded Google Chrome 158 behavior, nor that every discovered file can be processed without per-file error handling.

## Observed in existing Google Chrome 158.0.8127.37 profile

The separate file-URL probe was installed with **Load unpacked** in the user's existing Chrome profile, without touching the Clockoli extension or GitHub session. `isAllowedFileSchemeAccess()` was already `true` after installation; no file-access toggle click was needed. Configuration containing only the two local root URLs and one nested sample file URL per provider was stored in the probe extension's own IndexedDB and read back. There was **no probe extension page** opened. The `chrome://extensions` tab was then closed, and both that tab and any probe extension page were confirmed absent at 18:01:14 CET on November 24, 2026.

After waiting more than five minutes, at 18:06:22 CET the tabs were still absent. The probe worker's persisted status advanced from alarm run 9 (before the wait) to alarm run 15: `fileAccessEnabled: true`, trigger `alarm`, Codex 136 directories / 636 entries / 501 JSONL files and Claude 35 directories / 75 entries / 34 JSONL files, with zero listing errors and no backlog. For each provider, `fetch(file://known-nested-file)` returned 200 and read a bounded 4096-byte fragment containing a complete JSONL line. Raw line text, directory paths and filenames were not output. **A full restart of this existing Chrome profile was not performed**: the user chose cleanup rather than closing their other tabs/sessions. The probe's alarm and IndexedDB were removed and read back as absent, `uninstallSelf()` retired its worker target, and the Chrome extensions UI showed the probe absent while the installed Clockoli remained present. The temporary verification tab was closed. The broad file permission is no longer granted to the probe.
